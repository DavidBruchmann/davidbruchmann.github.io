TYPO3, Design, Templating and Features

Design and Templates are fully solved with TYPO3, even the playlist for the Media Player is created with an extension and Icons are loaded with TYPO3 viewHelpers. On base of this setup it's easy to add new layouts, sub-pages or features. TYPO3 as "Content Management System" fulfills its role here literally!
In the following chapters you find details about different features of this website which all are solved with TYPO3.

Eye-catching header with scroll-progress and most basic navigation items

The top of the interface is anchored by a persistent, space-efficient header that houses the core branding and primary utility toggles. To give users an immediate visual anchor without cluttering the screen layout, the header itself serves as eye-catching scroll-progress bar especially due to it's coloring and color-changes of icons on scrolling. As the user moves down a page section, the indicator bar dynamically fills from left to right, providing intuitive spatial feedback across long-form layout content.

The navigation canvas itself is stripped down to the absolute essentials to preserve breathing room on smaller viewports. It contains only the primary logo alongside a unified row of functional toggles:

  • Language Selector: Switches between localized route branches (/en/ and /de/).
  • Appearance Switcher: Toggles the site's dark and light aesthetic styling themes.
  • Media-Player Trigger: Slides out the decoupled background audio controller panel.
  • Hamburger Menu: Offers access to the website's page navigation.

To keep the application light, responsive, accessible and reliable, the sub-menus for these items use a CSS-driven slide-in concept. Rather than executing JavaScript for animations, the slide-in menus utilize CSS and are in this point entirely accessible and free of need for JavaScript.

The Web-Audio Player

Tailored Playback and Seamless Control

While standard web development often relies on the browser's native <audio> element, that default approach introduces strict visual and functional limitations. Native audio controls look different in every browser, cannot be customized easily with stylesheets, and are designed primarily to play a single, isolated audio file rather than managing an ongoing compilation. This custom web-audio player bridges those gaps by decoupling the user interface from the underlying audio stream.

Key Architectural Advantages

  • Complete Styling and Design Freedom: Because the interface is built using standard HTML, CSS, and vanilla JavaScript, the player's layout is completely customizable. Controls, text outputs, container drawers, and custom vertical volume sliders can be styled to match the site's brand identity. This ensures a consistent look and feel across all browsers and devices, completely bypassing the rigid, un-stylable default browser player shells.
  • Continuous Playlist Automation: Standard audio tags require manual user interaction to load and play subsequent files. This custom integration features an intelligent sequence engine that tracks playlist indices, handles track changes via direct clicks, and automatically triggers the next track when the active audio stream reaches its natural end.
  • Simple Extendability: Additional elements and functions can easily be added to meet increased requirements or demands.
  • Interactivity: When several playlists are prepared and saved, the option exists, even on static websites, that users could select between playback of different lists. In common (dynamic) TYPO3 installations an extension could handle user-choices, without the need to save anything in advance.

Diverse Application Scopes

The flexibility of a decoupled, continuous audio environment opens up several practical installation possibilities across different digital platforms:

  • Music Frameworks & DJ Decks: Traditional portfolios, band websites, and music hubs can present clean albums or background track lists that users can skip through, control, and browse seamlessly without page flashes.
  • Podcasts & Series Networks: Audio content platforms can queue up sequential episodes, save playback positions, or display custom episode metadata displays natively beside the controls.
  • E-Learning & Language Courses: Educational portals can bundle sequential audio lectures, step-by-step pronunciation guides, or audiobooks. Because the player runs inside a persistent frame, students can complete worksheets, flip through study modules, or take notes on different pages while the lesson audio continues to play uninterrupted.
  • Guided Audio Tours & Storytelling: Museum guides, real estate walk-throughs, and interactive travel blogs can sync specific tracks to structural location maps or article sections, providing an automated narration layer as the visitor explores the content.
  • Ambient Soundscapes & Focus Workspaces: Platforms focusing on wellness, meditation, or deep-work productivity can deliver looping background noise channels, white noise configurations, or focus beats that flow continuously in a low-overhead, accessible container.

CMS independent features

TYPO3 as Content Management System serves entirely as platform to produce this website, including design, templates and all technical features. There are two important features though which are build independently on top of that, which are described in the following short chapters.

Single Page Application (SPA)

While this website has many features that use JavaScript, it's almost fully functional even without it. 
As hybrid solution JavaScript enables one important feature though, that is the Single Page Application (SPA), which means that the site isn't loading entirely fresh on page-change, but differing content and elements are replaced in the initially loaded page, therefore the site allows cross-page features like for example the media-player, which would be interrupted or reset otherwise.
The user-experience is more comfortable, as new content is loaded in predefined areas but no full page reloads do happen usually. This comfort won't be consciously recognized by inexperienced users but those rather will feel that everything works somehow smoother than on other pages.

The Static Mirror

Publishing Static Websites means that those don't have a server which can react on user-input. There isn't any database, no server-side software which is able to react on users' interactions. Instead static websites have very limited options to respect user-choice, if not realized directly in the code itself.

This project is deployed as a fully static installation hosted on GitHub Pages (via github.io). Because a hybrid SPA fallback architecture relies cleanly on raw HTML files and client-side JavaScript routers when decoupled from the backend database, it can be exported effortlessly into a serverless format. Running the platform as a static website introduces several major architectural advantages:

  • Impenetrable Security: Without an underlying database, active content management execution loops, or PHP processing threads on the production mirror, the common attack vectors for data breaches, SQL injections, and backend exploits are completely eliminated.
  • Maximum Performance and Global Loading Speeds: The website consists entirely of pre-rendered, lightweight assets that do not require server-side compilation time. These static files are delivered instantly over global content delivery networks (CDNs), leading to minimal time-to-first-byte (TTFB) metrics.
  • Maintenance-Free Infrastructure: There are no database engines to optimize, no server operating system patches to monitor, and no scaling bottlenecks to manage. The mirror remains consistently stable and cost-effective regardless of sudden traffic spikes.
